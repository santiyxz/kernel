Insights

            
How protected each server actually is, exactly how the next weekly report will read, and the coin economy without typing a slash command.

          

        


        

          

            

              
Security scorecard

              —
              
            

            
The same readiness score the weekly digest uses, with the findings behind it. “Fix” opens the setting that clears the finding; restore-point findings are slash commands.

            

            
          


          

            

              
Digest preview

            

            
The exact embed the next weekly report would post. Nothing is sent.

            
            

            
          


          

            

              
Economy

              —
            

            
Top balances in the selected server, read from the same wallets /cash uses. A change records its reason in the server history; “set” replaces the balance, so it asks for SET.

            

              
              
              
              
              
              
            

            

              
              
            

            

          


          

            

              
Layout & readiness drill

              —
            

            
What the restore point remembers, what it would rebuild right now, and the order Kernel would act in during a real nuke. Rebuilding creates channels and roles, so it asks for RESTORE.

            

              
            

            

              
              
              
              
              
            

            

            

          


          

            

              
Usage & growth

              —
              
            

            
Which commands servers actually run, and members joining or leaving over the last 30 days. Counting starts when this bot build boots, so the first days are honest zeros rather than invented history.

            

            

            

            
          


          

            

              
Feature adoption

              —
              
            

            
Which servers have each feature switched on, read from their stored settings. A row with only anti-nuke lit is a server that installed Kernel and never finished setup.

            

            
          

        

      


      

        

          

            
Operations

            
Announcements that wait for a set time, members watched across every server, the last few builds kept for rollback, and messages the Contact page sends.

          

        


        

          

            

              
Scheduled broadcasts

              —
              
            

            
The same embed and sender as Broadcast, queued in data/meta.json so a host restart inside the window still delivers. A post missed by more than the grace window is reported as skipped, never sent late.

            

            

              
              
              
              
              
              
            

            

            

              
              
            

          


          

            

              
Watchlist

              —
            

            
One member id, checked on every join. An alert posts to the Incidents route; a kick or ban runs before the welcome and asks for WATCH. A failed action is reported with Discord's reason, never retried in a loop.

            

              
              
              
              
              
              
            

            

              
              
            

            

            
Recent matches

            

          


          

            

              
Release manager

              —
            

            
Copies src/ and package.json into data/builds/ — settings are never part of a build. The last five are kept. Restoring writes a pre-restore copy and replaces the source; the new code starts after the next restart.

            

              
              
              
            

            

          


          

            

              
Messages

              —
              
            

            
Everything sent from the Contact page or a developer profile, kept in data/inbox.json (last 500). Reply opens your mail client with the visitor's address already in the To field; nothing is sent from here.

            

            

              
            

          

        

      


      

        

          

            
Safeguards

            
Backups, broken references, a grouped error list and a one-button check of the whole deployment. Nothing here changes anything until you press a button.

          

        


        

          

            

              
Backups

              —
            

            
A copy of every settings file, kept on the bot (last 10). Download one before a deploy, or restore after a bad change. Restoring replaces all settings, so it asks for the same typed confirmation as a broadcast.

            

              
              
              
            

            

          


          

            

              
Broken references

              
            

            
Saved channel and role IDs that no longer exist, features switched on with no channel, and the permissions each switched-on module needs. Read-only.

            

            
          


          

            

              
Error inbox

              —
              
            

            
Crashes grouped by stack and counted, kept on the bot across restarts. A repeating stack is one row with a count, not a wall of lines.

            

            
          


          

            

              
Deployment doctor

              
            

            
Tunnel, CORS, owner, admin routing, data folder and environment names. It only reads; secret values are never shown.

            

            
          

        

      


      

        

          

            
Live log

            
The last few hundred lines this process printed. A restart clears it.
