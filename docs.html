Documentation

Set it up in the order you would actually do it.

Seven short pages, no video course. Each section says what the feature does, the command that turns it on, and what a member sees when it fires. If a step is missing, that is a bug — tell us.

1 · Setup

Invite Kernel with the permissions it asks for, then run /setup in the server. The command creates a private log channel, stores the server id, and reports what is still missing. Nothing is pre-enabled: anti-nuke and automod stay off until you turn them on.

StepCommandWhat it changes
Join/setupCreates the log channel and stores the server id
Check/setup againLists missing permissions and disabled modules
Guard/antinuke enableTurns on the threshold monitor
Gate/verifysetup checkReports whether the member gate can run

Keep your existing hierarchy. Kernel never needs the top role. It acts through the permissions you grant, and it refuses to punish members whose role sits above its own.

2 · Anti-nuke

Anti-nuke watches destructive actions rather than messages: channel deletes, role deletes, bans, webhook creation and permission grants. Each action is counted against the actor inside a short window. When a count passes the threshold, Kernel revokes the actor's dangerous roles, reverts what it can and writes a report to the log channel.

What you configure

  • Thresholds per action, so a moderator cleaning up five channels is not treated like a compromised token.
  • Whitelist of roles or users who are never auto-punished.
  • Punishment — strip roles, timeout, or ban, applied in that order of severity.

What gets logged

The actor, the action, the target, the count that tripped the threshold and what was reverted. Cases are stored with an id so you can review them later instead of scrolling a channel.

Test with a spare role. Give a test account a role below Kernel's and delete one channel. If the report does not appear, the bot is missing Manage Roles or Manage Channels.

3 · Cases and moderation

Every warn, timeout, kick and ban writes a case with a number, the moderator, the target and the reason. /case view shows it, /case history lists a member's past cases, and /case edit fixes a reason without deleting the record.

CommandUse
/warnWrites a case and DMs the member
/timeoutTemporary mute with a duration
/kick /banRemoval with a required reason
/case historyAll cases for one member, newest first
/case editCorrect a reason on an existing case

Moderation commands require a manager role or Manage Messages. When a member tries one without permission, the reply is private — nobody else in the channel sees the refusal.

4 · Automod

Automod is the message-level layer: invites, mention spam, link spam, excessive caps and repeated messages. Rules are independent. A message can trip two rules and is only acted on once.

  • Invites — Discord invite links, deleted and logged.
  • Mentions — over a per-rule limit, timeout or delete.
  • Links — allow list per channel, everything else removed or quarantined.
  • Caps and spam — length-relative caps ratio and repeated-message detection.

Each rule has an action: delete, warn, timeout or quarantine. Quarantine is a temporary permission strip, not a kick; the member keeps their roles and can be released with one command.

Allow lists beat block lists. If a channel is meant for links, allow it there rather than teaching the rule every domain you trust.

5 · Verification

Verification gives new members one button. Pressing it grants the verified role; until then, the gate keeps them out of the channels you choose. There is no captcha, no external site and no data stored beyond the grant itself.

CommandUse
/verifysetup checkReadiness report: role, channel and permissions
/verifysetup startPosts the button and enables the gate
/verifysetup repairRe-posts the button if the message was deleted
/verifysetup stopRemoves the gate and stops granting the role

Verification records the member id and the time of the grant. It does not record an IP address, browser, location or login history — there is nothing to leak because nothing is collected.

6 · Logging

Logging is grouped by event rather than dumped in one channel: joins and leaves, message edits and deletes, role changes, channel changes and moderation actions. Each group can point at a different channel.

  • Moderation — case created, edited, revoked.
  • Members — join, leave, role added or removed, nickname change.
  • Messages — edit, delete, bulk delete, attachment removed.
  • Server — channel and role create, delete and permission overwrite.

Log channels are private by default. If you move them, re-run /setup so the bot knows where to write.

7 · Roles and the dashboard

The dashboard signs you in with Discord OAuth and shows only servers where you hold Manage Server or a role Kernel recognises as staff. Everything it can change is also a slash command, so a broken dashboard never locks you out of configuration.

  • No Administrator. Kernel asks for the specific permissions it uses.
  • No stored passwords. Sign-in is OAuth; the site never sees a Discord password.
  • No hidden admin badge. Staff tools are gated by your Discord id server-side; other members see nothing different.

If you lose access because you changed roles, ask a server owner to re-grant Manage Server or use the slash commands directly.

Support

Setup stuck on a missing permission? Open the support server and post the output of /setup — it lists exactly what is missing. For bugs, include the case id or the channel where it happened; no screenshots of tokens, please.
