Permissions & data

What Kernel can touch, and what it keeps.

The invite link requests Administrator, because a full restore of channels and role overwrites can need more than any single named permission. The table below is what Kernel actually uses, so you can also invite it with a role holding only those permissions. Its data stays in local files on its own host, and the records are listed on the privacy page.

Administrator is not on that list. The invite link requests it because a restore of complex channel overwrites can need more than the named set. If Kernel holds Administrator, run /security audit: it lists every account and role holding it, including Kernel’s own.

Where it runs

  • Outbound only. The bot connects to Discord; it does not open an inbound game or voice port.
  • The dashboard is served by the bot through the same web server as its API. There is no separate database server to secure.
  • Owner tools need both a Discord sign-in and the owner’s Discord id. Anyone else gets a 404 from /api/owner/*, not a 403 that confirms the page exists.
  • Secrets stay in the host environment. The bot token lives in the host’s environment variables; it is never written to the data folder and never shown in the panel.

Safeguards

  • Case history is hash-chained. Editing one field breaks every hash after it and moves the chain head, which is mirrored in a second file. /cases export keeps a copy Kernel cannot rewrite.
  • Snapshots are local. Anti-nuke restore rebuilds from a snapshot of channel and role names and permissions, not from a cloud service.
  • Backups are attachments. A backup is a JSON file sent to your admin server; the same file can be imported again.
  • The status board is one message that gets edited, not a stream of new posts.
  • Admin routing reports failures. A post that could not be delivered is recorded with the reason and shown in the owner console and /kernel logs.

What it never does

  • No mass DM, no self-bot behaviour, no joining servers on its own.
  • No permanent message archive. Automod reads a message to decide and keeps no copy; the last ten deleted messages per channel stay in memory for /snipe and empty on restart; configured log events post one embed to the channel you chose.
  • No third-party analytics, advertising pixels or fingerprinting on the site.
  • No plaintext passwords, IP addresses or login history — see the privacy page for the full list.

Reporting a security issue

Send a private message with what happened and how to reproduce it. Never post a bot token, an owner session or a panel password in a public issue or a support thread. If a token was exposed, reset it in the Discord Developer Portal first and tell the owner afterwards.
